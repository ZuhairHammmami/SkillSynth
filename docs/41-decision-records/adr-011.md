# ADR-011: Post-Rebuild Consolidation (layers, cache/scheduler wiring, isolated tests, canonical DDL, separate admin app)

Note: Superseded by ADR-013 — the cache/ and infrastructure/ layers described here were removed.

## Status
Superseded by ADR-013 (schema specifics: 29→15 tables, seed v3, DDL 003_reduced_schema.sql; the operational points — dead-layer removal, isolated test DB, separate admin app — remain in force). Historical evidence below cites tooling that has since been removed.

## Context
After the post-rebuild completion pass, several structural facts needed a recorded decision: two backend layers (`mappers/`, `validators/`) turned out to be dead code; caching and background scheduling existed but were not wired into request/lifecycle paths; the test suite previously risked touching the dev database; schema truth lived only in ORM models with no canonical DDL; and the admin UI's location (inside the student frontend vs. its own app) was ambiguous.

## Decision
1. **Remove `mappers/` and `validators/` layers** from `src/backend/` — dead code, 0 imports.
2. **Wire active layers**: `cache/` uses SimpleCache decorators wired to `/api/public/stats` (TTL 30s); `infrastructure/` runs a daemon scheduler (hourly expired-session cleanup) started in `main.py` lifespan.
3. **Isolated test DB**: conftest creates a temp SQLite DB per pytest session, seeded from seed_v2 data; dev DB never touched. pytest/httpx declared in requirements.txt.
4. **Canonical DDL**: introduce `src/migrations/002_rebuild_schema.sql` (29 domain tables, strict 3NF; duplicate Path columns dropped) as schema source of truth, verified against ORM by `tools/verify_schema.py`.
5. **Admin app as a separate service** confirmed at `src/admin-app/` (:3001, English-only) — not inside the student frontend.

## Consequences
- Backend layer count drops to 13; no mapper/validator indirection remains.
- Public stats are cached (30s staleness acceptable); expired sessions are cleaned hourly without cron.
- Tests are hermetic and parallel-safe; seed data changes propagate automatically via conftest reuse of seed_v2.
- DDL drift is caught by running the verifier instead of manual inspection.
- Admin deploys/version independently of the student app at the cost of one more Next.js process.

## Evidence
```bash
PYTHONPATH=src python -m pytest tests/ -q      # 67/67 passed, isolated temp DB
python tools/verify_schema.py                  # SCHEMA MATCH
PYTHONPATH=src python seed_v2.py               # ~1519 rows; PRAGMA foreign_key_check gate passes
grep -rn "mappers\|validators" src/backend --include="*.py" -l   # no matches
```

## Options Considered
1. Keep mappers/validators "for future use" — rejected: dead code violates file-hygiene rules and misleads contributors.
2. Redis-backed cache + external cron — rejected for dev scope: SimpleCache decorators + in-process lifespan scheduler cover current needs without new infrastructure.
3. Shared DB between tests and dev — rejected: mutation risk and non-reproducible runs; temp DB per session chosen.
4. Derive schema from `Base.metadata.create_all` only — rejected: no reviewable artifact for prod PostgreSQL; canonical SQL file chosen.
5. Fold admin back into `src/frontend/src/app/admin/` — rejected: different auth audience, English-only locale, independent release cadence.
