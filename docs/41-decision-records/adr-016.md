# ADR-016: Grounding the local LLM in project data + GPU runtime fix (no fine-tuning)

## Status
Accepted

## Context
ADR-015 made the local 3B model (Q6_K, `src/data/Llama-3.2-3B-Instruct-Q6_K.gguf`) the SS-AI engine in-process. Two operational problems remained. (1) **The model was ungrounded**: it received only a skill's name + difficulty + `skill.topics` and never the canonical `description`, category, prerequisites, or the seeded assessment bank — so generated quizzes/narratives could misrepresent the real catalog. (2) **The runtime was broken in production style**: `skillsynth run` launched the backend with an `LD_LIBRARY_PATH` that omitted `/opt/cuda/lib64`, so the CUDA build of `llama-cpp-python 0.3.35` failed to resolve `libcudart.so.13`/`libcublas.so.13` at load → the recurring SS-AI startup error. (CUDA 13.3 IS installed at `/opt/cuda`; it was simply not on the loader path for the spawned backend.) Additionally the `AI_N_CTX` default (1024) under-used the 4 GB GTX 1650 Ti, and `_path_progress_list` still did an N+1 step query per path.

Retraining is infeasible locally (no torch; 3B Q6_K needs ~10-16 GB VRAM to fine-tune; 1650 Ti has 4 GB), so accuracy must come from **in-prompt grounding on project data** rather than weight updates.

## Decision
1. **CUDA runtime fix (prerequisite)**: `backend/cli.py` gains `_cuda_lib_dir()`/`_ensure_cuda_ld_library_path()` which append the detected CUDA lib dir to `LD_LIBRARY_PATH` before spawning the backend (probes `CUDA_HOME`/`CUDA_PATH`, `CUDACXX`, then `/opt/cuda/lib64`). Result: the model loads in-process with GPU offload under `skillsynth run`. `doctor --strict` now runs a real `_ai_runtime_probe` (loads the GGUF once + one tiny completion) so loader/OOM/corrupt-GGUF failures surface as a FAIL row instead of a silent crash.
2. **Data grounding via a persistent in-memory knowledge layer** (`services/knowledge_layer.py`, ≤300 lines): a lazy, thread-safe catalog digest of skills (description/topics/category/prerequisites) + up to 4 existing bank questions per skill, plus a compact whole-catalog digest. `skill_context(skill_id)` and `knowledge_digest()` feed bounded "Project reference" blocks into `llm_prompts` quiz/analysis templates. Invalidated via `catalog_service.invalidate_skill_cache()` (one piggyback line), so every catalog write keeps prompts fresh — no retraining needed.
3. **Accuracy over training, bounded context**: grounding is injected in-prompt (bounded char cap) so context stays inside `n_ctx` on the 4 GB card; the deterministic engine and bounded-autonomy −1/0/+1 policy are untouched (ADR-015 stands).
4. **Speed & reliability**:
   - `ai_n_ctx` default raised to **4096** (benchmarked on the 1650 Ti at 26 auto-fitted GPU layers: ~3.0 GB VRAM, ~1 GB headroom, no latency penalty vs 1024).
   - `llm_engine.complete()` now forwards an optional constrained **GBNF `grammar`** (`AI_GRAMMAR=false` default; off keeps behavior unchanged) so structural JSON validity is guaranteed when enabled, cutting malformed-JSON retries. The salvage+retry ladder remains the safety net.
   - Analytics `_path_progress_list` N+1 replaced with the existing `get_steps_by_path_ids` batch (1 query instead of N+1).
5. **Maintainability**: `llm_pipeline.py` was 334 lines (> the 300 rule); parsing/salvage helpers moved to `services/llm_validation.py` (120 lines) and re-exported from `llm_pipeline` so existing callers/tests are untouched. Zero schema changes — the 15-table DDL stays frozen (SCHEMA MATCH).

## Consequences
- SS-AI quiz/narrative output is now grounded in the real catalog: it references an actual skill's description, topics, category and existing question style instead of extrapolating from a bare name.
- `skillsynth run` no longer fails to load the model; `doctor --strict` proves load+GPU health; `health()` now reports `gpu_layers` + `free_vram_mb`.
- 2x+ context budget (1024 → 4096) at identical latency; grounding is bounded so it never crowds out the smaller KV headroom under load.
- One new env flag `AI_GRAMMAR` (default off; constrained-grammar opt-in). Enabling it trades a little output style variety for guaranteed-valid JSON.
- Test suite grew to 349 passing (9 new: knowledge_layer digest/context/invalidate + pipeline context-forwarding/grammar-gating + config default). `SCHEMA MATCH (15 tables)`.
- Corrects ADR-015's "CPU-only" note: the installed build is CUDA-capable and CUDA 13.3 is present at `/opt/cuda`; GPU offload is the default operating mode via `_fit_layers`, degrading to CPU only when VRAM is occupied.

Supersedes the CPU-only qualification in ADR-015 and its note that nvcc was absent; adds grounding + reliability hardening. Deterministic guarantees and the bounded-autonomy policy are unchanged.
