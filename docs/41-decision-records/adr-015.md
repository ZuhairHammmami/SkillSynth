# ADR-015: Local LLM Integration (in-process llama.cpp GGUF, bounded autonomy, two-phase wizard)

## Status
Accepted

## Context
The domain docs declared "no LLM in the loop" (05-domain): scoring, proficiency, and path generation were purely deterministic. SS-AI keeps that engine as the source of truth but adds a local LLM for quiz generation, weakness narrative, per-question explanations, and post-submit proficiency review. An earlier Phase-4 attempt had left dead Ollama/OpenAI/langchain dependencies and env blocks plus a docker `ollama` service; those were removed outright before this work. Sourcing hit reality twice: the bartowski Hugging Face mirror returned 401 (download unavailable), and the user ruled to **reuse the already-present artifact** at `src/data/Llama-3.2-3B-Instruct-uncensored.Q6_K.gguf` (2,967,059,008 B) rather than fetch a verified-standard copy — GGUF header metadata identifies standard Meta Llama 3.2 3B Instruct with no abliteration markers, and the legacy filename is kept for provenance honesty. Tooling also bit: Python 3.14 has no prebuilt llama-cpp-python wheel on this machine (source build fallback), nvcc is absent so the installed build is CPU-only, and the GTX 1650 Ti's 4 GB VRAM makes full offload of ~2.76 GB weights + KV cache tight — GPU offload (`CMAKE_ARGS="-DGGML_CUDA=on" pip install llama-cpp-python --force-reinstall --no-cache-dir`) requires the CUDA toolkit, while `AI_N_GPU_LAYERS` is a safe no-op on the CPU backend.

## Decision
1. **In-process serving**: `llama-cpp-python` 0.3.x loads one GGUF file directly in the FastAPI process (`services/llm_engine.py`); no extra service, no provider chain.
2. **Five endpoints** behind an `AI_ENABLED=false` default gate → 503 when off: POST `/api/ai/wizard-quiz`, POST `/api/ai/tests/generate`, POST `/api/wizard/analysis`, POST `/api/ai/explain`, GET `/api/learning/analysis`.
3. **Two-phase wizard**: `/wizard/analysis` is PURE (zero writes) — detailed results + weaknesses are presented *before* path creation; generation itself stays deterministic.
4. **Ephemeral vs persisted**: wizard AI quizzes are ephemeral (job id + SSE delivery only); standalone practice tests persist as real assessments titled `[AI] <Skill> — adaptive`, so results/analytics flow unchanged.
5. **Bounded autonomy**: post-submit review may adjust proficiency by −1/0/+1, ONLY at confidence==high, clamped 0..5, audited in `activity_log(action='ai_proficiency_review')` + SSE `proficiency_adjusted`. The deterministic formula is never overwritten by raw model output.
6. **Degradation ladder**: `AI_ENABLED=false` → 503 gates everywhere; model missing/corrupt → `LLMUnavailable` latch → quiz ops raise (SSE `ai_quiz_failed`/`ai_test_failed`) while analysis/explain fall back deterministic-only (`narrative_available:false`) and review returns delta 0.
7. **Config** (env): `AI_ENABLED(false)`, `AI_MODEL_PATH`, `AI_N_GPU_LAYERS(-1)`, `AI_N_CTX(4096)`, `AI_TEMPERATURE(0.3)`, `AI_REPEAT_PENALTY(1.15)`, `AI_TOP_P(0.95)`, `AI_MAX_NEW_TOKENS(700)`.

This supersedes ADR-010's local-first *provider chain* idea with a concrete single-provider implementation; its local-first intent and deterministic-fallback spirit survive. Conventions follow ADR-013 (small single-purpose modules, feature-gated surface) and ADR-014 (structured error payloads); zero schema changes — the 15-table DDL stays frozen.

## Consequences
- API grew 63 → 68 OpenAPI operations across 49 → 54 paths (7 → 8 routers incl. `ai`).
- Test suite grew to 178 passing tests (isolated temp DB; AI tests monkeypatch the engine, so all green without a model).
- Five new SSE events: `ai_quiz_ready`, `ai_quiz_failed`, `ai_test_ready`, `ai_test_failed`, `proficiency_adjusted` (alongside existing `assessment_completed`/`path_generated`).
- VRAM budget: 4 GB card fits Q6_K 3B only partially offloaded; CPU-only inference is slower but functional (`AI_N_GPU_LAYERS` harmless no-op there).
- Python 3.14 caveat: expect source builds for llama-cpp-python until wheels land; pin/document the toolchain in 51-ai-integration.
- The model artifact ships outside git-tracked code hygiene assumptions (large binary in `src/data/`); filename ≠ metadata truth, documented for provenance.
- Determinism guarantees (topological ordering, scoring formula, unanswered-skill retention) are untouched and pinned by the same tests as before.

## Options Considered
1. Ollama server (docker sidecar) — rejected: extra service lifecycle, duplicate model management, and the dead Phase-4 config proved nobody maintained it; in-process loading consumes the exact GGUF path with zero orchestration.
2. Hosted API (OpenAI-class) — rejected: recurring cost, data egress of learner answers, offline-hostile, and contradicts ADR-010's local-first posture.
3. In-process llama-cpp-python — chosen: simplest deployment (pip dependency), exact-file control, graceful degradation hooks we own, CPU/CUDA swappable at install time.
