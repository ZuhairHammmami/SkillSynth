# ADR-017: AI path-generation speed — batched completions, trimmed token ceilings, decoupled narrative via SSE

## Status
Accepted

## Context
Even after ADR-016 (grounding + GPU runtime fix + `n_ctx` 4096), **path generation stayed slow — "far beyond a few minutes"** for the wizard/AI flow, and AI-enriched questions "weren't appearing." Root cause was measured (read-only DB + code inspection), not assumed: the slowness was entirely in the **AI enrichment layer**, never the deterministic path math.

- `generate_role_quiz` (`llm_pipeline.py`) did **one ~650-token `create_completion` PER SKILL**. A role has **12–20 skills** (Full Stack 20, Frontend 16, …), each completion ≈ **~23 s** on the 4 GB GTX 1650 Ti (~28 tok/s) → a 16-skill role ≈ **6+ min** of serial generation. AI questions therefore streamed one skill at a time, minutes apart.
- `POST /api/wizard/analysis` ran `analyze_diagnostic` (max 750 tokens ≈ **~27 s**) **synchronously on the HTTP request thread** (`paths.py:_attach_narrative`). The produced narrative was identical in shape to the deterministic numbers-only fallback and the student frontend did not even render it — so every wizard-path generation blocked ~27 s for a narrative nothing displayed.
- ADR-016's `AI_GRAMMAR` opt-in grammar is off by default (per an earlier selection), so malformed-JSON retries remained possible — making any per-completion cost doubly expensive when it triggered.

Deterministic `/api/generate-path/` endpoints were already batched + fast (no LLM, no SSE) — the complaint mapped solely to the AI layer above them.

## Decision
Target the actual cost drivers: **fewer completions, smaller completions, and no synchronous LLM on the request path.**

1. **Batch role questions** (`llm_pipeline.generate_role_quiz`): chunk the role's skills into groups of **4** (`_ROLE_BATCH`) and run **ONE completion per batch** via a new `role_quiz_batch_prompt` (JSON array `[{skill, text, options, correct_index}]`) instead of one-per-skill. A 16-skill role drops from 16 completions to 4. Batching lives in a new ≤300-line `services/llm_batching.py` layering under `llm_pipeline` (lazy imports avoid a module cycle). **Fallback**: an all-empty batch (truncation/malformed) splits in half and retries, bottoming out at per-skill `generate_skill_quiz` — coverage is never lost. `on_skill` still fires per skill so SSE streaming UX is preserved.
2. **Trim `max_tokens` ceilings** (safe, contract-preserving — salvage still catches truncation):
   - `generate_skill_quiz`: `max(650, n*230)` → `min(700, max(180, n*95))` (n=2 ⇒ 190 vs the old 650 ≈ **3.4× smaller**).
   - `analyze_diagnostic`: 750 → **400**.
   - `explain_result`: 950 → **500**.
   - `generate_skill_topics` (400) and `review_level` (240) unchanged.
3. **Decouple the blocking narrative**: `POST /api/wizard/analysis` no longer calls `analyze_diagnostic` synchronously. It returns instantly with `narrative: null, narrative_available: false` plus a new `analysis_id` (uuid), and — when AI is enabled + engine ready — spawns `_narrative_job` on a daemon thread (`_spawn`) that computes the narrative (its own `SessionLocal`, grounded via `knowledge_layer`) and emits a new SSE `narrative_ready {analysis_id, narrative}` frame. The frontend (wizard `+page.svelte`) listens for `sse:narrative_ready`, matches on `analysis_id`, and merges the narrative into the shared analysis state; `ReviewStep` renders it when it arrives. Soft — any job error just skips the frame.
4. **Keep `AI_GRAMMAR=false`** (per the user's earlier selection) — the split-and-retry fallback + salvage ladder covers malformed batching output; no grammar flip.

## Consequences
- **Path/wizard AI enrichment drops from minutes to seconds**: a 16-skill role quiz goes from ~16 sequential ~23 s completions to 4 batched completions (~4× fewer), each with ~70% smaller `max_tokens` on the per-skill path. `/api/wizard/analysis` is now **effectively instant** (no synchronous ~27 s LLM block).
- AI-enriched questions arrive per-skill sooner and the full set far faster ("questions not appearing" resolves).
- Contract change: wizard-analysis `narrative`/`narrative_available` now arrive **asynchronously** via `narrative_ready` SSE (identified by `analysis_id`) instead of inline. The endpoints/tests that asserted the old synchronous inline narrative were updated to the new contract. Existing callers that only use the deterministic fields are unaffected.
- New SSE event `narrative_ready` (user channel) — the student `sse.ts` registers it; documented in 51-ai-integration.
- Deterministic generation, bounded autonomy, zero-write analysis, and the 15-table schema are all unchanged (`SCHEMA MATCH`).
- One new service module `services/llm_batching.py`; `llm_pipeline.py` stays ≤300 lines.
