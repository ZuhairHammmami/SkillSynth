# ADR-013: Feature Reduction to 15-Table Core (RBAC/notifications/sessions dropped, API rebuilt)

## Status
Accepted

## Context
The 29-domain-table schema carried substantial dead weight: 5 tables had zero live consumers (`step_progress`, `resource_progress`, `resource_tags`, `resource_sources`, `profile_preferences`), `audit_logs` writes already flowed into `events`, the `users` table was nearly vestigial (auth ran on `profiles`), granular RBAC existed but every UI consumed only the `is_admin` boolean, and no frontend consumed notifications. The objective: a strict-3NF core of 11-14 tables where every table and relationship is exercised by a precise API, with divide-and-conquer code (few files, small files, single-purpose documented functions).

## Decision
1. **Consolidate to exactly 15 tables** (one documented JSON exception per user approval):
   - `users` absorbs `profiles` (email, hashed_password, full_name, is_admin).
   - `skills.category_id` replaces the `skill_categories` junction (single category per skill).
   - `user_skills` replaces `profile_skills`, upgraded from name-string to real `(user_id, skill_id)` FK.
   - `step_progress` merges `step_completions` + `step_progress` (completed_at NOT NULL = complete; DTO synthesizes `is_completed`).
   - `activity_log` merges `events` + `audit_logs` (single `data` JSON column; `category ∈ {audit,auth,system,learning,realtime}`).
   - `assessment_questions` normalizes the question bank (position/prompt/options/correct_index); `options` remains one JSON attribute (approved exception).
2. **Drop entirely**: `roles`, `permissions`, `role_permissions`, `user_roles` (binary `is_admin`), `notifications`, `sessions` (stateless JWT), `resource_tags`, `resource_sources`, `resource_progress`, `profile_preferences`, `events`, `audit_logs`, `profiles`.
3. **Remove Alembic**: schema truth = canonical DDL + ORM create_all + seed_v3; `alembic.ini`, `src/migrations_alembic/`, and the meta-table are gone.
4. **Rebuild API surface**: 13 legacy router files → 7 routers (`auth`, `learning`, `paths`, `assessments`, `analytics`, `admin`, `realtime`); 85 operations → 55 operations across 45 paths. Every existing frontend URL and response field preserved verbatim (verified by curl table in Task 3).
5. **Divide-and-conquer code**: layered dirs kept (entities/dto/repositories/services/routers/policies/middlewares/events) but consolidated — 20 entity files → 5, 12 dto → 4, 11 repos → 5, 20 services → 6, 17 routers → 8. Every function ≤40 lines with a docstring stating its single purpose and its caller/callee relationships.
6. **Dead layers deleted**: `commands/`, `queries/`, `cache/`, `infrastructure/` (scheduler died with sessions); SSE pub/sub kept in `events/publisher.py`; public-stats 30s TTL cache re-implemented inline in `main.py`.

## Consequences
- Auth is binary (admin/student): the admin Roles page, settings roles card, and student admin-hook surfaces were removed from both frontends; i18n shrank 824 → 575 leaf keys (parity kept).
- Reset-password is stateless (signed 30-min JWT); no email delivery in dev — documented.
- Test suite rewritten: 79 tests, isolated temp DB seeded via seed_v3 (1109 rows), green ×2, dev DB untouched.
- Files shrank across the stack (e.g., backend: 20→5 entity files, 20→6 services); seed data module intentionally exceeds the line cap.

## Options Considered
1. Keep granular RBAC — rejected: zero UI consumers beyond `is_admin`; 4 tables for a dead feature.
2. Keep notifications — rejected: no consumer anywhere; SSE live-stream preserves realtime UX.
3. Keep sessions + scheduler — rejected: JWT auth is stateless; the cleanup task existed only for the dropped table.
4. Keep `skill_categories` M:N — rejected: no skill belongs to multiple categories in practice; single FK is 3NF-faithful.
5. Keep Alembic for prod — rejected for now: PostgreSQL deployment is not live; DDL + verifier give equivalent guarantees; reintroduce when prod migration is actually needed.
6. Keep questions as JSON on assessments — user-approved normalization instead: `assessment_questions` table (+1 over the 14 baseline), `options` JSON retained as the single documented exception.
